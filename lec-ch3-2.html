3.4 六大高级提示词技巧

技巧1：分步骤提问法（大任务拆小）

原理：一次性让 AI 做太复杂的任务，它容易遗漏细节、质量下降。把大任务拆成小步骤，一步一步来，每一步确认后再进行下一步，质量更高。

实战流程：

步骤你做什么示例提示词
第1步：规划让 AI 先给方案，不写代码"我想做一个个人主页，请先帮我规划：需要哪些文件、页面结构是什么、每个部分有什么内容。先不要写代码。"
第2步：确认方案你审查方案，调整后确认"方案不错，但我想把技能展示改成图标+文字的形式，项目展示加一个截图占位。确认后开始写代码。"
第3步：生成框架让 AI 先生成 HTML 结构"好，按照确认的方案，先生成完整的 HTML 结构，包含所有部分的内容占位，CSS 先写最基础的布局。"
第4步：美化样式结构确认后，再优化样式"结构没问题，现在优化 CSS 样式：主色调深蓝色，卡片式布局，加平滑的过渡动画，响应式适配手机。"
第5步：加交互样式确认后，再加 JS 交互"样式很好，现在加 JS 交互：导航栏滚动效果、技能进度条动画、项目卡片 hover 效果。"
⚠️ 注意
新手常见错误：一上来就说"帮我做一个完美的个人主页"，结果 AI 生成的东西四不像。正确的做法是先规划、再结构、再样式、再交互，一步一个脚印。

技巧2：截图/图片辅助法（一图胜千言）

原理：有时候你想要的效果很难用文字描述清楚，直接给 AI 看一张参考图，它就能精准理解。

适用场景：

  • 想要特定的页面布局或设计风格
  • 看到一个好网站想模仿
  • UI 设计稿转代码
  • 报错截图让 AI 分析

使用方法：

  1. 截图你想要参考的页面或设计
  2. 在支持图片的 AI 工具中（Trae、GPT-4o、豆包等），把图片拖入对话框
  3. 配合文字说明："参考这个设计风格，帮我做一个类似的个人主页，但内容换成我的信息"

提示词模板：

参考这张图片的【设计风格/布局/配色/交互效果】，帮我【做一个XX页面/修改现有代码】。

具体要求：
1. 【功能需求1】
2. 【功能需求2】
3. 【风格要求：保持参考图的XX特点，但XX部分按我的要求调整】

约束：
1. 只用原生 HTML/CSS/JS
2. 【其他约束】

输出完整的可运行代码。

技巧3：苏格拉底追问法（让 AI 帮你想清楚）

原理：很多时候你自己都没想清楚要什么，直接让 AI 做肯定做不好。这时候可以让 AI 反过来问你问题，帮你把需求想清楚。

使用方法：

我想做一个【项目名称】，但需求还没想清楚。请你以产品经理的身份，向我提问，帮我把需求梳理清楚。

要求：
1. 一次只问 3-5 个最关键的问题
2. 问题要具体，不要太宽泛
3. 每个问题给出 2-3 个选项供我参考（如果适用）
4. 等我回答后，根据我的回答继续追问，直到需求足够清晰

我目前的想法是：【描述你目前模糊的想法】

实战例子：

你说："我想做一个校园二手交易平台，但还没想清楚。"

AI 问：

  1. 这个平台主要交易什么类型的物品？（A. 教材书籍 B. 电子产品 C. 生活用品 D. 全部都有）
  2. 用户怎么发布商品？（A. 填写表单发布 B. 发图片+文字 C. 两者都有）
  3. 买卖双方怎么联系？（A. 平台内聊天 B. 显示微信号/QQ C. 显示手机号）
  4. 第一版需要哪些核心功能？（A. 发布+浏览+搜索 B. 再加分类筛选 C. 再加聊天和收藏）

你回答后，AI 继续追问，直到需求清晰。然后再让 AI 开始写代码。

技巧4：让 AI 自我审查（生成 → 审查 → 修正）

原理：AI 生成代码后，让它自己审查一遍，找出问题并修正。这能大幅减少 bug。

使用方法：

刚才你生成的代码，请以严格的代码审查员视角，自己检查一遍。

检查清单：
1. 有没有语法错误？
2. 有没有逻辑错误？（比如变量未定义、函数名拼写错误）
3. 有没有遗漏我要求的功能？
4. 有没有 XSS 安全风险？（用户输入直接插入 DOM）
5. 边界情况处理了吗？（空输入、特殊字符、快速操作）
6. 代码中有没有明显的性能问题？

如果发现问题，请列出问题并给出修正后的完整代码。如果没有问题，也请明确说明"已检查，未发现问题"。

进阶用法：可以用两个不同的 AI 工具交叉审查——A 工具生成代码，B 工具审查找 bug。不同模型的盲点不同，交叉审查能发现更多问题。

技巧5：项目规则文件（.cursorrules / 项目规范）

原理：在项目根目录创建一个规则文件，定义项目的编码规范、技术栈、目录结构等。AI 工具（Trae、Cursor 等）会自动读取这个文件，在整个项目中遵守你的规则。

使用方法：

在项目根目录创建一个名为 .trae/rules 或.cursorrules 的文件，内容如下：

# 项目规则

## 技术栈
- 纯 HTML/CSS/JavaScript，不使用任何框架和库
- CSS 使用 Flexbox 布局，不使用 Grid
- JavaScript 使用 ES6+ 语法

## 编码规范
- 变量和函数使用 camelCase 命名
- 代码中必须加中文注释
- 缩进使用 2 个空格
- 字符串使用单引号

## 设计规范
- 主色调：#3182ce（蓝色）
- 圆角：8px
- 字体：系统默认无衬线字体
- 设计风格：简洁现代，不要花哨动画

## 安全要求
- 用户输入必须经过转义后再插入 DOM，防止 XSS
- 不使用 eval()
- 不使用 innerHTML 插入用户输入内容

## 其他
- 所有功能必须兼容 Chrome 和 Edge 浏览器
- 响应式设计，手机端宽度 375px 以上正常显示

创建后，Trae/Cursor 在这个项目中生成或修改代码时，会自动遵守这些规则，不需要每次都在提示词里重复。
