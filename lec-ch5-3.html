5.4 第三步：多轮迭代优化

初版生成后，不要期望一次完美。接下来通过多轮对话，逐步优化。每一轮只改一个或几个点，不要一次性提太多需求。

5.4.1 第二轮：优化整体样式和布局

如果初版的整体风格和你预期有差距，先调整大的样式：

个人主页初版已经生成了，整体结构不错，但样式需要调整：

1. 主色调从深蓝色改成【你想要的颜色，比如：清新的青绿色 #0d9488】
2. 首屏区域的高度占满整个视口（100vh），内容垂直居中
3. 导航栏的毛玻璃效果再明显一些，加个底部阴影
4. 项目卡片的圆角加大到 16px，阴影更柔和，hover 时上浮 8px 并加阴影
5. 技能进度条加动画效果：页面滚动到该区域时，进度条从 0 动画增长到目标值
6. 整体字体加大一号，行高增加到 1.8，阅读更舒适
7. 各个区块之间的间距加大，增加留白感

只修改样式，不改变 HTML 结构和功能。给出修改后的完整代码。

5.4.2 第三轮：添加交互动效

样式满意后，添加一些交互动效，让页面更有活力：

在当前个人主页基础上，添加以下交互动效：

1. 滚动出现动画：页面滚动时，各个区块的内容从下方淡入上移出现（用 Intersection Observer 实现）
2. 导航栏高亮：滚动到对应区块时，导航栏中对应的链接高亮显示
3. 打字机效果：首屏的一句话介绍用打字机效果逐字显示
4. 回到顶部按钮：页面滚动超过一屏时，右下角出现“回到顶部”按钮，点击平滑滚动到顶部
5. 项目卡片 hover 时，图片有缩放效果（scale 1.05），加过渡动画
6. 技能进度条动画：之前加过，确认在滚动到该区域时触发
7. 所有动画加 will-change 和合适的缓动函数，保证流畅

不改变现有布局和内容，只添加动画效果。给出完整代码。

电脑端满意后，检查手机端的显示效果，进行适配：

检查并优化个人主页的手机端显示效果（宽度小于 768px）：

1. 导航栏：右侧导航链接隐藏，变成汉堡菜单按钮，点击展开/收起菜单（带动画）
2. 首屏：头像缩小到 120px，姓名和介绍字体缩小，两个按钮上下排列
3. 关于我：左右布局变成上下布局，图片在文字上方
4. 技能：进度条宽度 100%，技能名和百分比上下排列
5. 项目卡片：从一行 3 个变成一行 1 个，卡片宽度 100%
6. 联系方式：三个联系方式从横向变成纵向排列
7. 整体内边距减小到 16px，避免内容太挤
8. 检查所有文字在手机端是否清晰可读，字体不小于 14px

5.4.5 第六轮及以后：细节打磨

内容替换后，再仔细检查一遍，做最后的细节打磨：

  • 错别字检查：通读一遍，有没有错别字、语句不通顺的地方
  • 链接检查：所有按钮和链接是否能正常跳转（GitHub、邮箱等）
  • 图片替换：把占位图换成你自己的头像和项目截图（可以用图床或本地图片）
  • SEO 优化：修改 title 和 meta description，让搜索引擎能正确收录
  • 性能检查：页面加载速度、动画是否流畅
  • 多浏览器测试：在 Chrome、Edge、手机浏览器中都打开看看

发现问题就继续和 AI 对话修改，直到你满意为止。记住：完成比完美更重要，先有一个 80 分的版本上线，后面可以慢慢优化。

5.5 常见问题与解决方案

问题1：AI 生成的代码太长，被截断了

解决方案：输入“继续”或“接着写”，AI 会从截断的地方继续写。如果多次截断，可以让 AI“分文件生成”——先生成 HTML 结构，再生成 CSS，最后生成 JS。

问题2：页面打开是空白的，什么都不显示

解决方案：按 F12 打开开发者工具，看 Console 面板有没有红色报错。常见原因：JS 语法错误导致页面渲染中断、CSS 选择器错误、HTML 标签没有闭合。把报错信息复制给 AI，让它修复。

问题3：导航栏点击不滚动，或者滚动位置不对

解决方案：检查导航链接的 href 是否和对应区块的 id 一致（比如 href="#about" 对应 id="about"）。检查 CSS 中是否有 scroll-behavior: smooth。如果滚动位置被固定导航栏挡住，给每个区块加 scroll-margin-top。

问题4：手机端布局乱了，元素重叠或溢出

解决方案：检查 @media 媒体查询是否正确生效。常见原因：元素设置了固定宽度（如 width: 800px）导致手机端溢出，改成 max-width: 100%。用 Flexbox 的 flex-wrap: wrap 让元素自动换行。

问题5：动画不流畅，有卡顿感

解决方案：动画属性用 transform 和 opacity（浏览器优化过），不要用 width/height/top/left 等（会触发重排）。给动画加 will-change 属性。减少同时触发的动画数量。

问题6：AI 改着改着把之前的功能改没了

解决方案：每一轮修改前，让 AI“先总结当前已实现的功能列表”，然后明确说“在保持现有所有功能的基础上，只修改XXX”。如果改坏了，用 Trae 的“时间线”功能回退到之前的版本。

问题7：头像和项目图片怎么换成自己的？

解决方案：1. 准备好你的头像图片（建议正方形，200x200 以上）2. 把图片放到和 index.html 同一个文件夹里，命名为 avatar.jpg3. 把代码中的图片地址从占位图改成src="avatar.jpg"4. 项目截图同理，命名为 project1.jpg 等，替换对应地址5. 如果要部署到网上，图片需要一起上传，或者用图床服务（如 SM.MS、Imgur）获取在线链接

问题8：页面在不同电脑上字体显示不一样

解决方案：这是正常的，因为不同电脑安装的字体不同。可以在 CSS 中指定字体栈：font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;，这样会优先使用系统默认的好看字体。如果一定要用特定字体，需要用 @font-face 引入字体文件（会增加页面加载时间）。

✅ 本章小结

本章关键点：

  1. 先想清楚再动手：动手前花 5 分钟规划页面结构、设计风格、准备个人信息。需求越清晰，AI 生成越精准。
  2. 第一轮用 CRCO 框架写提示词：上下文 + 需求（分点）+ 约束（技术栈、文件结构、设计风格）+ 输出要求。一次生成完整初版。
  3. 多轮迭代，每轮只改几个点：第二轮优化样式 → 第三轮加动效 → 第四轮响应式 → 第五轮替换内容 → 第六轮细节打磨。不要一次性提太多需求。
  4. 完成比完美更重要：先做出 80 分的版本，后面可以慢慢优化。不要在细节上死磕导致项目做不完。
  5. 学会用检查清单：完成后对照检查清单逐项验证，确保没有遗漏和 bug。
  6. 常见问题要会排查：白屏看 Console、导航不滚动检查 id 和 href、手机端乱检查媒体查询和固定宽度、动画卡用 transform/opacity。
  7. 你的个人主页是你最好的名片：做好后部署上线（第8章教），链接可以放在简历、社交媒体、邮件签名里，让别人一眼看到你的能力。
