认识 Vibe Coding —— 什么是氛围编程

第二篇 · 认知篇

1.1 从一个故事开始

想象一下：你有一个很棒的想法——做一个专门帮同学组队参加比赛的小网站。你去找会编程的朋友帮忙，他说："可以啊，不过我最近很忙，可能要等一个月。而且你这个需求还挺复杂的，前端后端数据库，少说也要做两三周。"

你叹了口气，想法就这样搁置了。

但现在，有了 Vibe Coding，情况完全不同了。你打开电脑，打开 Trae，用中文输入："帮我做一个大学生比赛组队网站，需要有发布组队信息、浏览队伍、申请加入、消息通知功能，界面要简洁好看。"

几分钟后，一个可以运行的网站出现在你面前。你点了点，发现某个地方不太对，又输入："把申请按钮改成蓝色，加一个队伍人数显示，再优化一下手机端的显示。"

又过了几分钟，网站改好了。你不需要写一行代码，不需要懂什么是前端后端，只需要用中文描述你想要什么。

这，就是 Vibe Coding。

1.2 什么是 Vibe Coding

官方定义

Vibe Coding（氛围编程 / 感觉编程）是由 OpenAI 联合创始人Andrej Karpathy 在 2025 年 2 月提出的一种全新 AI 编程范式。

Karpathy 的原话是：

"fully give in to the vibes, embrace exponentials, and forget that the code even exists."

（完全沉浸在感觉里，拥抱 AI 带来的指数级效率，忘掉代码本身的存在。）

通俗解释

一句话：你用自然语言说出想法，AI 帮你写代码，你负责验收和提修改意见。

更具体地说：

  • 传统编程：人 = 代码编写者，AI = 补全助手（帮你补一行代码）
  • Vibe Coding：人 = 指挥官 + 审核员，AI = 写代码的打工人

你不再需要逐行敲代码，不再需要记忆语法，不再需要查文档查半天。你只需要：

  1. 想清楚你要什么
  2. 用中文/英文描述给 AI 听
  3. AI 生成代码，你运行看看效果
  4. 不满意的地方，再描述给 AI，让它改
  5. 重复直到满意

一个类比

如果把做软件比作盖房子：

角色传统编程Vibe Coding
你建筑师 + 泥瓦匠 + 装修工（自己搬砖砌墙）业主 + 设计师（你说要什么，施工队来干）
AI递砖的小工（帮你递一下砖）整个施工队（设计、砌墙、装修全包）
你的工作学习怎么砌墙、怎么布线、怎么装修想清楚要几室几厅、什么风格、预算多少
效率几个月到几年几小时到几天

1.3 传统编程 VS Vibe Coding

用一张表看清楚两者的区别：

对比维度传统手写代码Vibe Coding
工作重心学习语法、框架、逐行敲代码描述需求、指挥 AI、审查结果
入门门槛高，需要学数月甚至数年低，会打字描述需求就能开始
开发速度慢，搭建环境就很久快，几十分钟做出 Demo
代码质量取决于个人水平，自己完全掌握AI 生成，需要人审查把关
适合场景生产环境正式项目、核心业务、高安全要求快速原型、小工具、Demo、学习验证想法、个人项目
核心能力算法、数据结构、架构设计、调试能力需求描述、提示词工程、结果判断、迭代优化
出错时自己查文档、调试、Stack Overflow把报错贴给 AI，让它分析修复
风险开发慢、人手不足代码黑盒、隐藏 Bug、技术债

1.4 Vibe Coding 的核心工作流程

Vibe Coding 不是一次性的"说一句话就完事"，而是一个迭代循环。掌握这个循环，你就掌握了 Vibe Coding 的精髓。

五步循环法

步骤你做什么AI 做什么关键要点
1. 描述需求用自然语言说清楚你要什么理解需求，规划实现方案越具体越好，功能、样式、技术栈都要说
2. 生成代码等待 AI 生成生成完整代码，创建文件第一次不要追求完美，能跑就行
3. 运行测试运行代码，试用功能，看效果—仔细看，记下哪里不对、哪里想改
4. 反馈修改把问题和修改需求告诉 AI分析问题，修改代码一次改一个点，不要一次性提太多
5. 重复循环回到步骤3，直到满意持续优化迭代是 Vibe Coding 的灵魂

核心心法：Vibe Coding 不是"一次生成完美作品"，而是"快速生成初版 → 持续迭代优化"。第一版丑、有 bug 都没关系，能运行就是胜利。后续通过一轮轮对话，把它打磨成你想要的样子。

实际例子：做一个待办清单

让我们用一个真实的例子走一遍这个流程：

第1轮：生成初版

你说："帮我创建一个待办清单网页，包含输入框、添加按钮、任务列表，用 HTML+CSS+JS，页面简洁美观。"

AI 做：生成 index.html，包含基本的输入框、按钮和列表。

你看：能运行，可以添加任务，但样式很朴素，没有删除功能，没有标记完成功能。

第2轮：加功能

你说："给每个任务加一个删除按钮，再加点复选框可以标记完成，完成的任务文字加删除线。"

AI 做：修改代码，添加删除按钮和复选框。

你看：功能有了，但颜色不好看，手机上显示有点挤。

第3轮：优化样式

你说："把主色调改成清新的蓝色，按钮加圆角，优化手机端的响应式布局。"

AI 做：调整 CSS，添加响应式媒体查询。

你看：好看多了！但刷新页面任务就没了。

第4轮：加存储

你说："把任务数据保存到浏览器本地存储，刷新页面不会丢失。"

AI 做：添加 localStorage 逻辑。

你看：完美！一个功能完整的待办清单做好了。

看到了吗？4 轮对话，从无到有，做出了一个完整的应用。这就是 Vibe Coding 的威力。

1.5 谁适合学 Vibe Coding

✅ 非常适合

  • 在校学生：快速做毕设 Demo、课程作业、竞赛原型、社团小工具
  • 非技术专业同学：文、经、管、艺等专业，想做工具但不会编程
  • 创业者 / 产品经理：快速验证产品想法，做 MVP（最小可行产品）
  • 内容创作者：做个人主页、作品集网站、互动小工具
  • 办公族：做数据处理小工具、自动化脚本、内部工具
  • 编程初学者：先用 AI 做出东西建立信心，再回头学原理
⚠️ 需要谨慎
  • 大型生产项目：涉及大量用户、核心业务、高安全要求的项目，不建议纯 Vibe Coding
  • 对代码质量要求极高的场景：如操作系统、编译器、金融核心系统
  • 需要深度性能优化的场景：AI 生成的代码可能不是最优的

最佳定位：Vibe Coding 最适合做个人项目、原型验证、小工具、学习练习。对于正式项目，可以用 Vibe Coding 快速生成初稿，然后人工审查、重构、优化。两者结合，效率最高。

1.6 常见误区澄清

误区1：Vibe Coding = 完全不用懂代码

事实：你可以不会手写代码，但至少要能看懂 AI 在干什么、判断结果对不对、看得懂报错信息。完全不懂的话，项目很容易失控。

这就是为什么课程第4章会教你"前端三剑客极简入门"——不求会写，求能看懂。

误区2：Vibe Coding 会让程序员失业

事实：Vibe Coding 不是替代程序员，而是改变程序员的工作方式。就像计算器没有让数学家失业，Photoshop 没有让设计师失业一样。AI 帮你写重复的样板代码，你可以把精力放在架构设计、业务逻辑、用户体验上。

而且，会 Vibe Coding 的程序员，效率是不会的人的 5-10 倍。未来不是 AI 替代人，而是会用 AI 的人替代不会用 AI 的人。

误区3：AI 生成的代码一定是对的

事实：AI 会"幻觉"，会生成看起来合理但实际有 bug 的代码，会引入安全漏洞，会用过时的 API。你必须审查和测试。这也是为什么"运行测试"是五步循环中不可或缺的一步。

误区4：提示词越长越好

事实：提示词的关键是清晰、具体、有结构，不是越长越好。一段啰嗦但模糊的长提示词，效果远不如一段简洁但精准的提示词。第3章会详细教你提示词工程。

误区5：一次就要生成完美的作品

事实：Vibe Coding 的灵魂是迭代。追求一次完美只会让你反复修改提示词、浪费时间。正确的做法是：先让它能跑起来，再一轮轮优化。"完成比完美更重要"。

1.7 Vibe Coding 的三种进化模式

随着你越来越熟练，Vibe Coding 也在进化。业内通常把它分为三个层次：

层次名称特点适合阶段
第一层Vibe Coding（氛围编程）凭感觉描述需求，AI 自由发挥，快速出原型初学者、快速验证想法
第二层Spec Coding（规范编程）先写详细的需求规格说明书，AI 按规范精确实现进阶用户、中等复杂度项目
第三层Harness Engineering（脚手架工程）搭建完整的开发环境、测试框架、CI/CD，让 AI 在受控环境中自主开发高级用户、团队协作、正式项目

本课程主要教第一层 Vibe Coding，并在第9章进阶技巧中简要介绍第二层 Spec Coding 的思路。第三层 Harness Engineering 涉及较深的工程知识，不在本课程范围内。

1.8 来自实战的 5 条方法论

根据大量实战经验总结，以下 5 条方法论是 Vibe Coding 成功的关键：

方法论1：痛点必须来自你自己

做项目前问自己："如果做不出来，明天还会被这问题折磨吗？"不会就别开始。解决自己真实痛点的项目，才有动力做完。

方法论2：PRD 写场景，不写功能

不要上来就列"功能1、功能2"，先写"用户在什么场景下遇到什么问题"。场景是给自己看的，功能是给程序员看的。想清楚场景，功能自然就清晰了。

方法论3：UI 阶段花的时间 > 编码阶段

AI 时代最反直觉的事：写代码变便宜了，做审美变贵了。你花在"找参考 → 调风格 → 改细节"的时间必须超过写代码。AI 不知道什么叫"好看"，这是人的核心价值。

方法论4：AI 提示词必须有验收标准

没有验收标准的提示词，必然翻车。"做完了"不等于"能用了"。每个需求都要写清楚"怎么算做完了"，比如"点击第3句，朗读第3句，不是第1句"。

方法论5：上线不是终点，反馈才是起点

产品上线后，用户反馈会驱动你快速迭代。很多最有价值的功能，都是上线后根据用户反馈加的。不要追求"完美了再上线"，先上线，再迭代。

1.9 本章小结

✅ 本章小结

本章你需要记住的关键点：

  1. Vibe Coding 是什么：用自然语言描述需求，AI 写代码，你验收和迭代。
  2. 核心流程：描述需求 → 生成代码 → 运行测试 → 反馈修改 → 重复循环。
  3. 关键心法：先跑起来，再慢慢优化，迭代是灵魂。
  4. 适合场景：个人项目、原型验证、小工具、学习练习。正式项目需人工审查。
  5. 你的角色：你是机长，AI 是副驾驶。你把控方向和质量，AI 帮你干体力活。
  6. 5条方法论：痛点来自自己、PRD写场景、UI时间>编码时间、提示词有验收标准、上线是起点不是终点。
