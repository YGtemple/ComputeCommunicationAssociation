实战项目二 —— 待办清单/日程助手

第七篇 · 实战篇（二）

6.1 项目概述

欢迎来到第二个实战项目！这一章我们将做一个待办清单/日程助手。

和个人主页（以展示为主）不同，待办清单是一个交互密集型应用，会用到大量 JavaScript 逻辑：添加、删除、完成、编辑、筛选、排序、本地存储。通过这个项目，你会更深入地理解 Vibe Coding 中“描述交互逻辑”的技巧。

我们将采用渐进式开发：先做最基础的待办清单（添加、删除、完成），然后逐步增加功能（本地存储、优先级、分类、统计、筛选），最后升级成一个功能完整的日程助手。

帮我创建一个待办清单（Todo List）网页应用。

6.8 待办清单常见问题

问题1：添加任务后列表不更新，或者显示重复

原因：渲染列表时没有先清空旧列表，导致重复追加。或者添加任务后没有调用渲染函数。

解决：让 AI 检查 render 函数，确保渲染前先list.innerHTML = '' 清空。每次数据变化后都调用 render() 重新渲染。

问题2：刷新后任务顺序乱了，或者完成状态不对

原因：localStorage 保存的数据结构不完整，或者读取后没有正确恢复状态。

解决：检查保存的数据是否包含 id、text、completed、priority、category 等所有字段。读取后检查每个任务的 completed 状态是否正确设置了复选框的 checked 属性。

问题3：删除按钮点击没反应，或者删除了错误的任务

原因：事件绑定有问题，或者删除时没有正确找到对应任务的 id。

解决：用事件委托（给列表容器绑定 click 事件，判断 e.target 是否是删除按钮），或者在创建元素时用闭包绑定正确的 id。让 AI 检查删除逻辑。

问题4：筛选后统计数字不对

原因：统计是基于全部任务计算的，而不是基于当前筛选后的任务。

解决：让统计函数接收当前筛选后的任务列表，基于筛选后的数据计算。或者在 render 函数中先筛选，再渲染，再统计。

问题5：编辑任务后，按 Esc 没有取消，反而保存了

原因：keydown 事件处理逻辑有误，或者输入框的默认行为没有阻止。

解决：检查 keydown 事件处理：Enter 保存，Escape 取消。确保e.preventDefault() 在需要时调用。

问题6：手机端输入框和按钮太小，不好点

原因：按钮和输入框的尺寸是为桌面端设计的，手机上触摸区域太小。

解决：在媒体查询中，把输入框和按钮的高度设为至少 44px（苹果推荐的最小触摸尺寸），字体不小于 16px（防止 iOS 自动缩放）。

✅ 本章小结

本章关键点：

  1. 渐进式开发：先做基础版（添加/删除/完成）→ 加本地存储 → 加优先级分类 → 加编辑筛选 → 优化样式 → 升级日程助手。一步一步来，每步确认后再继续。
  2. 交互逻辑描述要清晰：待办清单的核心是交互，描述需求时要说清楚“用户做什么操作 → 发生什么 → 数据怎么变 → 界面怎么更新”。
  3. 数据驱动思维：所有操作本质上都是在修改一个任务数组（增删改查），然后重新渲染页面。理解了这个，交互逻辑就清晰了。
  4. localStorage 是纯前端项目的数据命脉：记住 JSON.stringify（存）和 JSON.parse（取），第一次读取加 || [] 默认值。
  5. 每加一个功能都要测试：不要攒到最后一起测，加一个测一个，有问题立刻修。
  6. 完成比完美重要：基础版能跑起来就已经是胜利了。优先级、分类、日历这些都是加分项，有时间再做。
  7. 这个项目可以一直用：做好后部署上线，你自己每天都可以用它来管理任务。用着用着发现什么不爽，就继续迭代加功能——这就是最好的学习方式。
